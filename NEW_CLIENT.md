# Новый клиент → готовый сайт

Пошаговая инструкция: от заказа до рабочего сайта с заявками в Telegram.
Время: ~1 час, из них правка контента — 15–30 минут.

---

## 0. Что запросить у клиента

- [ ] Название, короткое описание, фирменный цвет (если есть)
- [ ] Телефон, адрес, часы работы, e-mail, WhatsApp / Telegram, соцсети
- [ ] Список услуг с ценами, прайс
- [ ] 6+ реальных фото работ и 1 фото для первого экрана
- [ ] 3+ реальных отзыва (имя, авто, текст), рейтинг на Яндекс.Картах / 2ГИС
- [ ] Цифры для счётчиков: стаж, число заказов и т.п.
- [ ] Домен (есть или купить) и **кто его оформляет** — лучше на клиента
- [ ] Куда слать заявки: Telegram (личка или рабочая группа)
- [ ] Текст **политики конфиденциальности** (или реквизиты, чтобы её составить)

## 1. Копия шаблона под клиента

Репозиторий `vutgen/avtopro-landing` — шаблон. Под каждого клиента — своя приватная копия
(замените `ivanov-auto` на имя клиента):

```bash
cd ~/Documents/VibeCoding/PORTFOLIO
gh repo create ivanov-auto --private --template vutgen/avtopro-landing --clone
cd ivanov-auto
```

> Так клиентские правки не попадают в шаблон, а у каждого сайта своя история изменений.

## 2. Контент

1. Всё меняется в **`js/config.js`** — по порядку сверху вниз (подробно — в `README.md`).
2. Фото клиента положите в папку `img/` и укажите пути вида `"img/hero.jpg"`.
   Размер: до ~300 КБ на фото, ширина 1200 px для первого экрана и 900 px для галереи.
3. В **`index.html`** поменяйте только `<title>`, `description` и `og:*`-теги в `<head>`
   (название города, бренд) — их читают поисковики и мессенджеры до запуска JS.
4. Проверьте локально:
   ```bash
   python3 -m http.server 8000
   ```
   → http://localhost:8000, плюс мобильная версия (в браузере: режим разработчика → телефон).
5. Сохраните:
   ```bash
   git add -A && git commit -m "Контент клиента" && git push
   ```

## 3. Демо для клиента (Netlify)

1. app.netlify.com → **Add new project → Import an existing project → GitHub**.
2. Если репозитория нет в списке: **Configure the Netlify app on GitHub** → добавить его в доступ.
3. Выбрать репозиторий. Настройки сборки не трогать (всё задано в `netlify.toml`) → **Deploy**.
4. **Project configuration → Change project name** → `ivanov-auto` → ссылка
   `https://ivanov-auto.netlify.app` — её и отправляем клиенту.

Дальше каждая правка: `git push` → через минуту обновлено по той же ссылке.

## 4. Заявки в Telegram

### 4.1. Бот (один раз на клиента, ~5 минут)

1. В Telegram: **@BotFather** → `/newbot` → имя (например, «Заявки Иванов Авто») →
   юзернейм на `_bot`. BotFather пришлёт **токен** — это пароль бота, никому не пересылайте.
2. Куда приходят заявки:
   - **в личку** — откройте бота и нажмите «Запустить»;
   - **в группу** (удобно, если заявки смотрят несколько человек) — создайте группу
     и добавьте туда бота.
3. Напишите что-нибудь боту / в группу, затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}` —
   это **chat id** (у групп он отрицательный, например `-1001234567890`).

### 4.2. Вариант А — сайт на Netlify

1. Netlify → **Project configuration → Environment variables → Add a variable**:
   - `TELEGRAM_BOT_TOKEN` = токен бота
   - `TELEGRAM_CHAT_ID` = chat id
2. В `js/config.js`: `formEndpoint: "/api/lead",` → commit → push.
3. После публикации отправьте тестовую заявку с сайта — она должна прийти в Telegram.

Обработчик: `netlify/functions/lead.mjs` (бесплатный лимит Netlify Functions для лендинга с запасом).

### 4.3. Вариант Б — российский хостинг с PHP (Timeweb, Beget, REG.RU…)

1. Скопируйте `api/lead-config.example.php` → `api/lead-config.php`, впишите токен и chat id.
   Этот файл **не попадает в git** — храните его только на хостинге.
2. В `js/config.js`: `formEndpoint: "/api/lead.php",`.
3. Загрузите все файлы сайта в корень сайта на хостинге (обычно `public_html`)
   через файловый менеджер панели или FTP. Папки `netlify/`, `.git/` загружать не нужно.
4. Отправьте тестовую заявку.

> Файл `api/.htaccess` закрывает прямой доступ к `lead-config.php` на хостингах с Apache.

## 5. Домен

- **Netlify:** **Domain management → Add a domain** → указать домен клиента → прописать у
  регистратора DNS-записи, которые покажет Netlify. HTTPS включится автоматически.
- **PHP-хостинг:** привязать домен в панели хостинга, включить бесплатный SSL (Let's Encrypt).

## 6. Чек-лист перед сдачей

- [ ] В `config.js` не осталось демо-данных: «АвтоПро», `avtopro-example`, `+7 (495) 123-45-67`,
      фото с Unsplash, придуманные отзывы
- [ ] `<title>` и `description` в `index.html` — про клиента и его город
- [ ] Тестовая заявка пришла в Telegram
- [ ] `contacts.privacyUrl` ведёт на настоящую политику конфиденциальности
- [ ] Телефон в шапке и кнопка звонка звонят на номер клиента
- [ ] Ссылки WhatsApp / Telegram / соцсети открывают аккаунты клиента
- [ ] Сайт проверен на телефоне
- [ ] Подключён домен, открывается по `https://`
- [ ] (По желанию) Яндекс.Метрика и Яндекс.Вебмастер

## 7. Персональные данные (152-ФЗ) — коротко

Форма собирает имя и телефон — это персональные данные, клиент становится их оператором.

- На сайте нужна **политика обработки персональных данных** и согласие (галочка уже есть).
- Клиенту стоит подать **уведомление в Роскомнадзор** об обработке ПДн (бесплатно, онлайн на pd.rkn.gov.ru).
- Обработчики из шаблона **не сохраняют заявки** — только пересылают в Telegram.
- Для боевых сайтов российских клиентов надёжнее **российский хостинг** (вариант Б).

> Это не юридическая консультация — точные требования клиенту лучше уточнить у юриста.
